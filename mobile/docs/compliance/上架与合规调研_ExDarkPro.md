## 0. 结论先行（11 条）

1. **最硬的阻塞不是商店，是资质。** 中国大陆主流商店已把「APP 备案」当上架前置条件，小米/腾讯/华为/三星四家页面都写明；小米还把「软著」列为**所有应用必交**三项之一。你现在两样都没有。`[已确认]`
2. **你现在这个包上不了任何一家商店，第一处就卡在签名。** [build.gradle](file:///c:/Users/Astra/Desktop/Roast%20PowerLifting/mobile/app/build.gradle#L19-L22) 的 release 用的是 `signingConfigs.debug`——debug keystore 是本机生成的临时密钥。备案要登记**公钥 + MD5**，商店要求跨版本签名一致，用 debug key 等于把「应用身份」建在流沙上。`[已确认]`
3. **「加 INTERNET 权限」这一步会改变你的备案路径。** 单机不联网 App 依规可免 APP 备案；一旦 App 自己发起公网请求（哪怕只查更新），就不再是单机，"免备案"这条路自动关闭。这是产品决策，不是开发细节。`[已确认]`
4. **七家里有一家不收个人：荣耀。** 荣耀官方文档写明「HONOR Developers services are only available for enterprises or organizations，个人开发者服务即将上线」。**个人身份现在上不了荣耀**，必须先有营业执照主体。你给的优先级「小米 > 荣耀 > vivo」在个人身份下要改成 **小米 > vivo > 荣耀（拿到企业主体后）**。`[已确认]`
5. 其余六家的真实门槛是「软著 + 备案 + 隐私政策 URL」，不是身份。入驻全部免费，卡人的是那三样材料。`[已确认]`
6. **软著是长周期项，且和「应用名称」死绑。** 法定 60 日、常见 20–30 工作日；名称与商店名、备案名三者必须一致，改名要重办。所以**先冻结应用名，再动其它一切**。`[已确认]`
7. **Google Play 技术上你已达标，流程上差三样**：AAB、Play App Signing、以及个人账号的「12 名测试者 × 14 天」封闭测试。targetSdk 37 > 2026-08-31 起要求的 36。`[已确认]`
8. **纯离线反而让 Play 的数据安全表单最省事**：仅在本机处理、不出设备的数据**无需申报**。但「健康应用声明」仍必须填（健身/训练属于 Activity & Fitness）。`[已确认]`
9. **器械品牌自由文本本身风险低，做成「品牌库 / logo 墙 / 官方合作暗示」风险高。** 中国商标法有指示性正当使用条款，但边界是「不造成混淆」；商店侧则是「未经授权的品牌素材」投诉即下架。`[已确认]`
10. **伤病字段是敏感个人信息，不是普通字段。** 哪怕只存本地，隐私政策也必须单独说明；一旦开云同步，就触发单独同意 + 个人信息保护影响评估，且跨境（GitHub/海外云）另有出境合规。`[已确认]`
11. **最快能落地的组合是：先做「纯离线版」上 2 家国内店，Play 走独立通道，别在 v0.84 阶段就引入联网。** 见 §8、§11。

### A6 提交动作序列（照着点）

1. 小米账号登录 `dev.mi.com` → 成为开发者 → 选「个人」→ 填姓名/身份证号/电话 → 上传身份证扫描件 + 手持照 → 提交（1–3 工作日）
2. 「创建应用」→ 填通用名称（≤30 字符，创建后不可改）+ 包名 `com.roast.exdark`
3. 上传 APK（v1+v2 已签、versionCode 递增）→ 系统自动读出包名/名称/版本，核对
4. 选设备类型（手机）、分类（运动健身）、分发地区（中国大陆）
5. 填资料：展示名 + 副标题（≤15 汉字/30 英文字符）、一句话简介（≤17 汉字/34 字符、陈述句、无极限词）、应用介绍、更新日志

## 2. 工信部 APP 备案

### 2.1 适用范围：离线 App 到底要不要备案

- 法规原文只对「在境内从事**互联网信息服务**的 APP 主办者」设义务，未履行不得从事该服务。来源：[工信部·关于开展移动互联网应用程序备案工作的通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)（2023-08）。`[已确认]`
- 通信管理局答复口径：「**单机不联网的 APP、小程序无需备案**」。来源：[工信部（内蒙古通管局）咨询答复](https://nmca.miit.gov.cn/jactpub/front/mailpubdetail.do?sysid=11&transactId=606118)。`[已确认]`
- 华为官方问答给出单机定义：「未通过连接**公共互联网**提供互联网信息服务的移动应用程序」，只有符合才可勾选「单机 APP」从而豁免。来源：[华为开发者问答·单机应用定义](https://developer.huawei.com/consumer/cn/forum/topic/0208229114585378624?fid=0102104600515103427)。`[已确认]`
- 小米备案指引同口径：「若 APP 本身内容是单机……则主办者不用为不联网的单机 APP 进行备案」，并给出被驳回后的单机申诉客服入口。来源：[小米·APP 备案指引](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1739)（更新 2026-10-25）。`[已确认]`

**但对你的产品，这条豁免很脆**：只要 release 包里有 `INTERNET` 权限并由 App 自己发起公网请求（例如启动时查 GitHub Release），它就不再满足「未通过公共互联网提供信息服务」。届时：

- 需要备案，且备案表要填 **APP 包名 + 公钥 + MD5 + 域名**（见 2.3）；
- 域名还得是**你主体名下、已完成 ICP 备案**的域名；
- 如果请求打到 GitHub/海外云，还叠加个人信息出境问题（IP、设备信息也算）。

**结论**：`INTERNET` 权限是「要不要走完整备案 + 出境合规」的分水岭。建议在 v0.84 这一版**先不加**，见 §11。

### 2.2 材料与路径

备案由**网络接入服务提供者或分发平台**的企业侧系统提交（实际就是阿里云/腾讯云/华为云等接入商备案系统），省级通信管理局终审。来源同上（小米备案指引 §四）。`[已确认]`

需要准备：

| 类别 | 内容 |
|---|---|
| 主办者身份 | 个人：姓名、证件类型/号码/有效期、应急联系电话、手机、邮箱、地址 |
| APP 基础信息 | APP 名称、图标、**服务类目**（运动健身）、语种、运行平台 |
| APP 特征信息 | 安卓包名 `com.roast.exdark`、**签名公钥 + MD5**、域名 |
| 前置审批 | 运动健身类通常无前置审批；若涉医疗/诊疗则另说（见 §6） |

**耗时**：接入商初审 1–3 工作日 + 管局审核，常见合计 **7–20 个工作日**（免费）。来源：[华为开发者社区·如何备案 APP](https://developer.huawei.com/consumer/cn/blog/topic/03207520486084184)（二手经验，非官方承诺）。`[需复核]`

### 2.3 与 ICP 备案的关系

- **APP 备案 ≠ ICP 备案**。官方 FAQ 明确：「已完成网站 ICP 备案还需要进行 APP 备案吗？→ **需要**」；「每个 APP 都需要单独备案」。来源：[小米·APP 备案指引 §七](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1739)。`[已确认]`

## 5. 商标与知识产权风险

### 5.1 法律侧

- 现行规则允许**指示性正当使用**：仅为指示所提供商品的用途、适用对象、应用场景或表明真实来源而使用他人注册商标，权利人无权禁止，**但容易导致混淆的除外**。来源：[国家知识产权局·中华人民共和国商标法](https://www.cnipa.gov.cn/art/2026/6/26/art_3685_206939.html)（2026-06-26 页面）。`[已确认]`
- 司法口径一致：销售商为指示所售商品而在善意、合理范围内使用商标，构成指示性使用，不侵权；**超出合理范围使公众误认存在关联的，可能侵权**。来源：[上海知识产权法院·许诺销售与商标使用](http://www.shzcfy.gov.cn/detail.jhtml?id=10010344)、[上海知识产权法院·商标指示性合理使用的司法认定](http://www.shzcfy.gov.cn/detail.jhtml?id=273525)。`[已确认]`
- 注意：有公开文章提到**新商标法自 2027 年起施行**、并把「商标使用」界定为「用于识别和区分商品来源的行为」。来源：[最高人民检察院·注册商标正当使用的边界](https://www.spp.gov.cn/spp/llyj/202611/t20261103_739905.shtml)（2026-11-03）。`[需复核生效日与条文号]`

### 5.2 商店侧（更现实的风险）

商店不做商标实质审查，但**权利人投诉即触发下架流程**，且「未经授权使用品牌 logo/图片」属于典型侵权投诉。所以风险分级是：

| 做法 | 法律风险 | 商店风险 | 判定 |
|---|---|---|---|
| 用户自由文本输入「Rogue / Eleiko / SBD」 | 低（用户生成内容 + 指示性使用） | 低 | **可做** |
| 内置品牌下拉库（Rogue、Titan…） | 中（你在主动使用他人商标做功能） | 中（可能被要求提供授权） | 不建议 |
| 内置品牌 logo / 产品图 | 高（美术作品 + 商标双重） | 高（投诉即下架） | **禁止** |
| 写「官方合作 / 认证 / 推荐」 | 高（虚假关联） | 高 | **禁止** |
| 品牌名做筛选项/统计维度 | 中（功能性使用，仍属指示性） | 中低 | 谨慎，保留免责声明 |

### 5.3 降风险的最低做法（可直接落地）

1. **只做自由文本**，不做品牌库、不做联想补全、不做 logo。
2. 输入框旁一行静态说明：「器械品牌/型号由用户自行填写，仅用于区分自有器材；相关名称与商标归各自权利人所有，本应用与任何器械厂商无隶属或合作关系。」
3. 用户协议加一条：用户保证其填写内容不侵犯第三方权利，且该内容仅本机可见。
4. 商店描述与截图**不出现任何第三方品牌名**（截图里的杠铃片如果有可见 logo，打码或换图）。
5. **应用名「ExDark Pro」本身要做商标检索**（第 41 类 教育娱乐 / 第 9 类 软件），并尽量同步申请注册。`[需复核：检索结果]` 名字一旦印在软著、备案、商店上，改名成本是「软著重办 + 备案变更 + 全渠道重新提审」。

## 7. 签名与密钥管理（个人开发者最容易踩的坑）

### 7.1 你现在的问题

[build.gradle](file:///c:/Users/Astra/Desktop/Roast%20PowerLifting/mobile/app/build.gradle#L19-L22)：

```gradle
release {
    minifyEnabled = false
    signingConfig = signingConfigs.debug
}
```

后果链：

1. debug keystore 由本机 `~/.android/debug.keystore` 自动生成，**换机器/重装 Android Studio 就可能换 key**；
2. 同一 `applicationId` 换了签名 → 老用户**无法覆盖安装**，只能卸载（你 `allowBackup=false`，卸载即丢全部训练数据）；
3. 备案登记的是**公钥 + MD5**，换 key 要**重新备案**；
4. 商店侧签名不一致会直接拒包，历史版本也无法延续。

### 7.2 正确顺序（顺序错了要返工）

```
生成正式 keystore（一次，永久）
   → 用它对 release 签名
   → 导出公钥 + MD5（备案要用；商店也要看）
   → 用同一 keystore 上传到各国内商店
   → 决定 Play 是否「上传自有密钥作为应用签名密钥」
```

### 7.3 关键决策：Play 与侧载能否共用一个证书

- Play App Signing 允许你**上传自己的密钥**作为「应用签名密钥」；此时 Play 分发出去的 APK 与你自己签的侧载包**证书相同**，用户可以在「Play 版 ↔ 官网版」之间互相覆盖升级。
- 若让 Google 生成密钥，则 Play 版证书 ≠ 你的侧载证书 → 两个渠道之间切换必须卸载重装（数据全丢）。
- **建议**：生成一个 release keystore，同时用于国内商店 + 侧载；在 Play 上选择「上传自有应用签名密钥」。代价是密钥副本在 Google 侧，收益是全渠道可平滑迁移。`[已确认机制，需在 Play Console 当日流程中复核]`

### 7.4 密钥保管

- keystore 文件 + 口令分开存放，至少两份离线备份；**不入 git**（当前 `.gitignore` 已排除 APK，需确认 keystore 也在排除项）。
- 一旦丢失：Play 侧可走「申请重置上传密钥」（需证明身份），**国内商店无法重置，只能换包名重新上架**——等于从零开始。这是个人开发者最致命、最不可逆的一步。
- 密钥轮换：Android 支持 APK Signature Scheme v3 轮换，但**商店侧不会自动接受**，国内渠道普遍要求签名永久一致。`[已确认：v3 支持轮换；国内商店要求需复核]`

1. **软著**（唯一的长周期项，且和应用名死绑）
2. **备案**（若走联网路径，还要先有 ICP 备案域名）
3. **隐私政策 HTTPS 可达性**（你自己的站点只有 HTTP）
4. **审核驳回循环**（通常是隐私政策不合规、权限说明缺失、截图含第三方 logo）
5. **荣耀的主体门禁**（不是耗时项，是「做不了」项：官方只收企业/组织，个人身份连入驻都进不去。有营业执照前，荣耀不计入「两家」）

> 因此 §8.1 的「两家」指 **小米 + vivo**。华为是第三家备选（软著非必选，可用受理通知书先试水），但不改变「两家长周期项并行」的结论。

## 9. 与现有分发方式的关系

### 9.1 是否冲突

**不冲突，但要分「同一份包」和「两套包」两种情况**：

| 方案 | 可行性 | 代价 |
|---|---|---|
| 同一个签名 + 同一个包名，商店与 GitHub/官网并行 | 可行 | 需要证书统一（见 §7.3）；商店可能要求「首发/独家」类商务条款，需逐家确认 `[需复核]` |
| 商店包与侧载包签名不同 | 功能可行 | 用户跨渠道迁移必须卸载重装 → 数据丢失（你 `allowBackup=false`） |

**不需要二选一。** 商店上架不影响你在 GitHub Release 与自建站继续分发；国内商店一般不禁「官网也有下载」，但个别渠道在商务合作中会提首发要求，签约前看清即可。

### 9.2 一个必须提前知道的行业变化：Android 开发者验证

- 自 **2026-09-30** 起，在巴西、印尼、新加坡、泰国，**已认证 Android 设备**上安装/更新应用，要求应用由**已验证开发者注册**；首批覆盖 7 家商店：Google Play、荣耀、OPPO(OPlus)、三星 Galaxy Store、传音 Palm Store、vivo、小米。
- **2027 年全球扩大**到「所有已认证 Android 设备上的所有应用」，并扩展到所有第三方商店。
- 仅侧载分发的开发者需在 **Android 开发者管理中心（ADC）** 注册账号、验证身份、注册包名；全面分发账号收费 **US$25**；「有限分发（≤20 台设备）」免费；未注册应用只能走 ADB/高级流程旁加载。
- 来源：[Android Developers·开发者验证指南](https://developer.android.google.cn/developer-verification/guides?hl=zh-cn)（页面更新 2026-09-11）、[开发者验证 FAQ](https://developer.android.com/developer-verification/guides/faq?hl=zh-cn)。`[已确认]`

**对你的含义**：你现在「GitHub Release + HTTP 镜像站」的侧载模式，在国内暂不受影响（首批四国不含中国），但**2027 年全球铺开后，纯侧载渠道会被要求开发者实名注册**。这不是「商店 vs 侧载」二选一的问题，而是**两条路都要实名**。提前把包名 + 签名 + 开发者身份三件事做对，两边都省事。

### 9.3 你的 HTTP 镜像站

- 商店审核与隐私政策要求通常隐含「可正常访问的 HTTPS 链接」；HTTP 站在部分渠道会被判「不安全链接」。
- 建议：给站点加 TLS（免费证书即可），HTTP 只做 301。**这会同时解决隐私政策链接、更新检查接口、以及 Play 描述里的官网链接三件事。**

## 11. 这个产品现在上架会被卡在哪一步

**一句话：卡在「第 0 步」——你的 release 包连一个稳定的身份都没有。**

按顺序会依次撞上：

1. **签名（立刻）**：`release` 用 debug 签名。备案要公钥+MD5、商店要跨版本一致、用户覆盖升级靠它。现在打包发出去的每一版，签名都可能随机器变。
2. **资质（1–8 周）**：无软著、无备案。小米/vivo/OPPO/应用宝是硬性要求；华为软著可后补但备案仍要。**荣耀这里还多加一道主体门禁**——官方只收企业/组织，个人身份材料再全也进不了入驻页（见 §1B），所以「荣耀」在个人身份下不是「慢」，是「不可行」。
3. **名称（不可逆）**：应用名未做商标检索、未冻结。软著、备案、商店名三者必须一致，改名等于三项重办。
4. **隐私政策（无 HTTPS 载体）**：仓内没有任何隐私政策/用户协议文本；站点只有 HTTP。这是最容易被驳回、也最容易提前解决的一项。
5. **联网权限（产品级岔路）**：加 `INTERNET` 就失去单机豁免，需要域名 ICP + 完整备案 + 可能的出境说明；不加就得改用「跳浏览器」式更新提示。
6. **健康合规（中风险）**：有伤病字段、有训练建议、有 1RM 估算。没免责声明会被判「医疗误导」；有免责声明但文案仍像诊疗，同样会被判。
7. **商店素材（低风险，耗时）**：图标/截图/年龄分级/分类，逐家规格不同。

**如果只做一件事**：生成正式 keystore 并把 `signingConfigs.debug` 换掉，同时冻结应用名。这两件不做，后面所有材料都会白做一遍。

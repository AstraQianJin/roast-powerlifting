## 1 · RPE < 5 夹到 5

### 1.1 行为定义（唯一口径）

| 输入 RPE | 行为 | e1RM 参与值 | 是否标注 |
|---|---|---|---|
| 5.0 – 10.0 | 原样使用 | 输入值 | 否 |
| 1.0 – 4.99 | **夹到 5** | 5 | 是 |
| 空 / `null` / `''` / 非数字 | 视为未记录（保持现状） | 无 RPE（rir=0） | 否（已显示"未记录"） |
| 0 或负数 | 视为无效（不是 RPE） | 无 RPE（rir=0） | 否 |

**为什么 0 不夹到 5**：`recordedRpeOf()` 已把实练 RPE 限制在 [1,10]，0 只可能来自脏数据或探针。把 0 当 5 会凭空抬高估算，违背"不补默认值"的红线。断言 G3b 会把这条边界钉死。

**连续性的准确含义**：夹取后 `4.9 → 5` 同值（`133.3 → 133.3`），曲线在 5 左侧是平台，不是跳变；`5 → 5.1` 才有斜率。

### 1.2 模板改动（`template.html`）

在 `e1rm` 上方新增唯一判定口：

```js
/* 实练 RPE 的唯一边界口径：1–4.99 夹到 5，5–10 原样；空/0/非数字视为未记录。
   targetRpe 只在没有实练 RPE 时使用，且仍只认 5–10（计划侧契约就是 5.0–10.0）。 */
function effRpeOf(rpe,targetRpe){
  const P=+rpe;
  if(P>=1&&P<5) return {rpe:5,clamped:true,src:'actual'};
  if(P>=5&&P<=10) return {rpe:P,clamped:false,src:'actual'};
  const T=+targetRpe;
  if(T>=5&&T<=10) return {rpe:T,clamped:false,src:'target'};
  return {rpe:null,clamped:false,src:'none'};
}
function e1rm(load,reps,rpe,targetRpe){
  const L=+load||0, R=+reps||0;
  if(!(L>0)||!(R>0)) return 0;
  const e=effRpeOf(rpe,targetRpe);
  const rir=e.rpe==null?0:Math.max(0,Math.min(5,10-e.rpe));
  const repCap=Math.min(12,R);
  return Math.round(L*(1+(repCap+rir)/30)*10)/10;
}
```

要点：

- `Math.max(0,Math.min(5,10-e.rpe))` 保留，但因为 `e.rpe>=5`，`Math.max(0,…)` 已成恒等；**不要删**，它保证将来若有人传入 10 以上也不会得到负 rir。
- `effRpeOf` 是**新函数**，必须登记进 `v3v.js` 的 `NEED` 名单（A0 名单机制会盯着），否则页面断言取不到它。
- 禁止在 `e1rm` 里再写第二份 `+rpe>=5` 判断。

### 1.3 界面标注

### 1.4 导出标注（CSV 26 列冻结）

**不能加列。** 唯一可用的自由文本列是 `notes`。做法：

- 常量：`const RPE_CLAMP_TOKEN='[RPE<5=>5]';`
- 导出 `EXERCISE` 行（当前模板 `recs.push({... notes:e.notes})` 处）：
  - 仅当 `recordedRpeOf(e)` 落在 [1,5) 时，`notes = withRpeClampToken(e.notes)`。
  - `withRpeClampToken` 先去重再追加，保证重复导出不叠加。
- 导出 `E1RM_LOG` 行：同样在 `notes` 写 `RPE_CLAMP_TOKEN`（该行本来不用 `notes`，不污染用户文本）。
- 导入侧（当前 `if(o.notes!=='') e.notes=o.notes;` 处）：写回前先 `stripRpeClampToken(o.notes)`，否则"导出→导入→再导出"会重复追加，D7/C4 的零格差会红。
- `actual_rpe` 列**写用户输入的原始值 4.5，不写 5**。夹取只影响 e1RM 估算，不改写事实。

导出行示意：

```text
...,"actual_rpe":4.5,...,"notes":"原备注 [RPE<5=>5]"
```

## 2 · GL 体重下限按性别

### 2.1 行为定义

| 性别 | 下限 | 低于下限 |

| 男 | 40 kg | 返回 0，界面显示"—" + 原因 |
| 女 | 35 kg | 返回 0，界面显示"—" + 原因 |

原因文案：

- 中：`体重 38.0 kg 低于男子 40 kg 下限，IPF GL 不计分`
- 英：`Bodyweight 38.0 kg is below the men's 40 kg floor; IPF GL not scored`

### 2.2 模板改动

```js
/* 单一出处：IPF GL 的适用体重下限（官方 2020 系数表）。 */
const GL_BW_FLOOR={M:40,F:35};
function glFloorOf(bw,gender){
  const B=+bw||0, g=(gender==='F')?'F':'M';
  return B<GL_BW_FLOOR[g]?GL_BW_FLOOR[g]:0;   // 0 = 未触底
}
function glFloorReason(bw,gender){
  const floor=glFloorOf(bw,gender);
  if(!floor) return '';
  const g=(gender==='F')?'F':'M';
  return L('体重 '+fmt(+bw||0,1)+' kg 低于'+(g==='F'?'女子':'男子')+' '+floor+' kg 下限，IPF GL 不计分',
           'Bodyweight '+fmt(+bw||0,1)+' kg is below the '+(g==='F'?"women's":"men's")+' '+floor+' kg floor; IPF GL not scored');
}
```

`calcIpfGl` 的 `if(bw<35) return 0` 改为：

```js
const B=+bw||0;
if(glFloorOf(B,gender)) return 0;
```

同时把 `d<=0` 的保护保留（当前分支里已有等价判断，别丢）。

## 3 · 段位用未取整 GL

### 3.1 拆分函数

```js
/* 计算真值：不取整。段位判定只准用这个。 */
function calcIpfGlRaw(total,bw,gender,equip,isBench){ ... return T*100/d; }
/* 显示值：两位小数。界面只准用这个。 */
function calcIpfGl(total,bw,gender,equip,isBench){
  const v=calcIpfGlRaw(total,bw,gender,equip,isBench);
  return v?+v.toFixed(2):0;
}
function currentGlRaw(){ const p=state.profile||{}; return calcIpfGlRaw((+p.sq||0)+(+p.bp||0)+(+p.dl||0),+p.bw||0,p.gender||'M',p.equip||'classic',false); }
```

约束：

- `calcIpfGl` 内部**只准**调 `calcIpfGlRaw`，不许再写一遍公式。
- `calcGlRank` 的入参含义变为"未取整 GL"；所有**计算出来**的 GL 都必须走 Raw。
- 已有历史快照里的 `gl` 是两位小数，无法还原真值。这类入口（计划库按 `s.gl` 着色）继续用存量值，属于已知局限，**不要为此改契约加列**。

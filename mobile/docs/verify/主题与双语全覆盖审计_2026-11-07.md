### 1.2 可疑待确认

- **Q1　配重预览的金属高光/夹片在亮底丢细节**：`.pv-bar::before` 顶部 `#D8E0EA`（vs 白 1.33）、`.pv-collar` `#E2E8F0`（1.23）、`.pv-clamp` 银阶（1.35）、`.plate-strip` 中段 `#C7CFDA`（1.57）。渐变下半段有 `#3E4652` 等深色，所以杠铃杆整体不会完全消失，但**顶部高光与夹片边线**会丢；是否达到「糊」需要截图。
- **Q2　器械图形的 idle 块在亮底可能粘连**：`.gz-block` 用 `--gear-idle`（light `#C3CDDA`，vs 白 1.61）+ `--line2`（`rgba(15,23,42,.065)`，合成约 1.2）描边。相邻 idle 块的分界可能只剩一条几乎看不见的线。器械图形本身已全部令牌化（这是对的），但亮底可读性未验证。
- **Q3　切主题不重绘「渲染时取色」的产物**：`applyTheme` 只改 `data-theme/data-mode` 并调 `paintThemeUI()`，不会重跑 `renderPoster` 等 canvas 绘制。CSS 变量类图形会自动跟随，问题只在「绘制时把颜色算成值」的 canvas/海报。由于切主题入口在设置页、海报等页面不并存，**当前大概率不可达**，列为结构风险而不是现网缺陷。
- **Q4　`.pv-clamp i` 5.5px + `letter-spacing:-.04em`** 在**所有主题**都难以辨认，不是主题专属，但会加重亮底问题。
- **Q5　`--dim2` 的实际用途**：若用于「可读的次要信息」则亮底 2.08–2.45 不合格；若只做装饰刻度则可接受。需要按调用点逐一定性。

### 1.3 合理项（不编造问题）

- 三主题令牌块**键齐全**：light / nature 都定义了全部 92 个颜色令牌；`:root` 多出的 13 个是时长、缓动、安全区等结构令牌，本就不应随主题变。
- 图表（`--fig-*`）与器械图形（`--gear-*`）**全部走令牌**，三主题各有一套值；这是本模板主题化做得最好的部分。
- 亮底覆盖虽只有 8 条（`html[data-mode="light"]`），但覆盖了 `.card`、`.btn-danger`、`.tab.on`、`.seg-pill`、`.gi`、`.ai`、`.wt` 等主结构，主面板不会出现「暗色阴影糊在纸上」。
- 三个主题的 `font-weight` / `font-family` / `-webkit-font-smoothing` **没有主题级差异**，字重一致性规则通过。
- `.pill.on`、`.done-btn`、顶栏品牌 SVG、`PLATES` 物理片色属于品牌/物理固定色，暗底亮底都成立，不应强行令牌化。

## 2. 语言清单（zh / en）

双语机制有两套：行内 `L(zh,en)`（约 L3175，`state.lang==='en'` 取 en）与 `I18N_NODES` 登记表（`applyChrome` 按 id 写入）。

### 2.1 确定错误

#### L1　`<html lang>` 永远是 `zh-CN`，切英文不更新

`<html lang="zh-CN" ...>` 是静态属性；全文没有 `documentElement.lang = ...`。`setLang()` 只改 `state.lang` 并局部重渲染。

后果：
- 英文模式下屏幕阅读器仍按中文发音规则读英文；
- CSS `:lang(en)` / `:lang(zh)` 无法用于排版修正（本报告 P1 的修法依赖它）；
- 浏览器断词、字体匹配、标点挤压仍按中文规则。

这是**结构性的 i18n 缺陷**，修一行即可（`setLang` 里同步 `document.documentElement.lang = state.lang==='en'?'en':'zh-CN'`），但必须补断言（见 A9）。

#### L2　GL 段位大字恒显示中文

`refreshGlHero` 中 `lb.textContent = r.labelZh`（L10016，元素 `#glLabel`，L1998）。`r.labelZh` 形如「白银 3★」。

英文模式下 `#glInfo` 用了 `L(...)`（正确），但`#glLabel` 仍是中文。这是顶栏每天可见的段位名，属于**确定的英文残留**。

#### L3　启动失败恢复链整屏中文单语

`markBootFatal`（L3254）、`bfNote`（L3628）、`renderBootFail`（L3633）共 15+ 条中文文案，全部直接拼接，没有 `L()`：
`'存档读取失败'`、`'只读模式'`、`'不覆盖原始文件'`、`'新建空账本'`、`'重试读取'`、`'已导出诊断'` 等，以及 L3731 的 `confirm('...')`。

英文用户一旦遇到存档恢复，会看到一个纯中文的阻断页。这是「数据安全路径」，必须双语。

#### L4　档位表（器械配重曲线）校验错误单语

`stackLevelsError`（L4887–4897）返回 7 条中文：
`'至少要有 1 个档位'`、`'档位最多 N 个'`、`'第 N 档不是数字'`、`'第 N 档超出 …'`、`'第 N 档必须比前一档高至少 …'` 等。该函数被 5 处调用（L4912 / 6088 / 6128 / 6176 / 6190），错误直接显示在档位表 sheet 里。英文模式仍显示中文。

#### L5　周期目标评估的 notes 单语

`auditCycleGoal` 返回的 `notes` 是中文数组（L10117），在 `ga-note` 里直接 `esc(a.notes[0])` / `map` 拼接（L10129、L10142）。标题 `CYCLE GOAL AUDIT` 会翻译，正文不会。

#### L6　计划导入 / 归档校验错误单语

`validateEnvelope`（L15269 起）与 `showPlanErrors`（L15336）里的错误串全部中文；归档取回失败时 `showPlanErrors(v.errors.join('\n'))`（L15368）。英文模式下导入失败会看到中文报错清单。

#### L7　策略库矩阵与卡片：行名、单元格、分类全是中文数据

`renderStratLib`（L12517–12556）：
- 行名直接 `esc(r.zh)`（L12529）；
- 单元格直接 `esc(String(v))`（L12532）；
- `cls()` 用中文正则判断样式（L12520–12522：`/不适用|^否$|^无$/`）；
- 分类过滤与卡片字段直接 `esc(s.cat)` / `s.lifts` / `s.params` / `s.scene` / `s.taboo`（L12553–12556）。

种子里的实际值（`seed.json` → `strategyLib.matrix[0]`）：
```json
{"zh":"恒重组","sq":"推荐","bp":"推荐","dl":"推荐（次数 ≤6）","ohp":"推荐","acc":"全部适用"}
```
英文模式下，图例已经翻译成“Green = recommended …”，表格里却仍是「推荐 / 限量 / 不适用 / 否」；策略卡片仍是「基础结构」「深蹲、卧推、硬拉、肩推；所有辅助动作」等中文。**这是语言清单里影响面最大的一条。**

#### L8　计划库 chips 与筛选下拉仍是中文数据

`renderProgLib`（L12382–12447）：
- 筛选选项直接 `esc(v)`，`v` 来自 `it.goal` / `it.auto`（中文“方法论 / 框架内置”）；
- 卡片 chips 直接 `esc(it.type/goal/auto/dur/ver/chg/note)`（L12436–12447）。

英文模式能看到中文筛选选项和中文徽章，只有计划名是双语的。

#### L9　HPR 内置指标单位在英文模式仍是中文

`hprBuiltin`（L8591 起）里 `unit` 写死为 `'分' / '米' / '组' / '次' / '轮'`；`hprBestText` / `hprTgtText` 直接拼 `(item.unit||'')`（L8765 / L8769），并在 L8821 展示。

英文模式会得到 `best 30分`、`target 10组` 这类混排。应存 `unit:{zh,en}` 或按类型映射为 `min/m/sets/reps/rounds`。

#### L10　英文路径输出全角中文标点

`L(part.zh, part.en) + '：'`（L5936，器械身份展示）。中文冒号不属于英文参数，英文模式会显示 `Brand：Series`。应把分隔符也放进 `L('：',': ')`。

#### L11　数据里 `en` 自身含中文

`seed.json` → `strategyLib.items[17]` 的 `en` 为 `Alternating Sets（主项轮转）`，`items[23]` 的 `en` 为 `Isometric Hold：Pin Press / 顶杠保持`。英文模式会直接显示括号中文和全角冒号。属于数据源（`data/*.xlsx`）缺陷，不是模板缺陷。

#### L12　周计划动作备注单语

`seed.json` → `weeks[w][day].exercises[*].notes` 是中文长句（例：`"W1 高杠蹲 3×5+ · 65.0% → 97.5 kg；周一 = Squat e1RM 唯一取样点"`），在 L7452 直接 `esc(e.notes)` 渲染，没有 en 字段。英文模式会在动作卡下方显示中文备注。

### 2.2 可疑待确认

- **S1　`setLang` 不重渲染已打开的 about 段落**：`openAboutSheet` 里写死的两段说明只在打开时赋一次；`setLang` 的重渲染清单没有 about。当前语言按钮在设置页、about 页没有语言入口，**大概率不可达**，列为结构风险。
- **S2　`en` 缺失时静默回落中文**：多处 `(x.en||x.zh)` / `(s.en||s.zh)`（L6504、6537、3796 等）。这是合理兜底，但意味着「数据缺英文」不会报错、只会静默显示中文；应加门禁而不是改运行逻辑。
- **S3　`catShort` 在英文下可能返回空串**：L11635 附近 `state.lang==='en' ? String(v.en||'') : ...`，若 `SHARE_SCHEMA.short_labels` 无 en，海报分类标签会空白。需要看实际契约数据才能定案。
- **S4　默认 readiness 文本存中文**：`d.readiness = READY[1].zh` 一类赋值；若某处直接回显存储值而不走 `L`，英文模式会显示中文。需要运行时核对 `readiness` 的所有消费点。

### 2.3 合理项

- `I18N_NODES` 共 **243 条**，全部为长度 2 的非空 `[zh,en]`，无 `en` 含中文，无重复 key；唯一「原样相同」的是 `advBadge: ["PREVIEW","PREVIEW"]`，属于徽章代号，可接受。
- `toast(...)`、空态、常规确认弹窗、图表图例、导出提示语**均走了 `L(...)`**（逐条扫描未发现漏网的中文 toast）。
- CSV 表头来自 26 列英文协议，导出文件名固定英文（`RPL_ExDark_v{VER}_export.csv` 一类），不受语言影响——这两处不需要本地化。
- 计划名、日标题、动作名等核心数据有 zh/en 双字段，且 `L`/三元选择正确。

## 3. 排版清单

### P1　中文标签吃字距（确定，系统性）

全 CSS 有 **81 条非零 `letter-spacing`**；自动核对到 **38 个选择器在中文模式下确实承载汉字**（人工复核后至少 30 个为确定，少量匹配是同行邻近文本造成的误配）。

典型确定项：

| 选择器 | 行号 | 字距 | 中文内容证据 |
|---|---|---:|---|
| `.stat label` | L409 | `.06em` | `#bwCardLbl` = 「体重」、`#doneCardLbl` = 「完成」（L1788/L1792） |
| `.panel-title` | L804 | `.03em` | `#edTitle` = 「调整动作」（L1850） |
| `.f-lbl` | L807 | `.08em` | 「训练模式」（L1860） |
| `.lbox label` / `.rbox label` | L515 | `.09em` | `L('载荷','LOAD')` → 中文「载荷」（L7424/7436） |
| `.add` | L600 | `.14em` | 「添加训练动作」（L1804） |
| `.aux-title` | L608 | `.04em` | 「一般身体准备」（L1808） |
| `.t-lab` | L737 | `.12em` | 「REST TIMER · 组间恢复」（L1826） |

| `.snap-head b` | L1487 | `.04em` | 「水平快照 · LevelSnapshot」（L2063） |
| `.ga-head b` | L1650 | `.04em` | 「周期目标评估」（L10126） |
| `.brand-sub` | L295 | `.13em` | `#hdrSub` 会被写入中文日标题（窄屏还叠加 nowrap + ellipsis） |

修法不要逐个删字距（英文标签需要 tracking）。推荐两种之一：
1. `setLang` 同步 `<html lang>`（先修 L1），然后加一条 `html:lang(zh) .stat label, html:lang(zh) .panel-title, … { letter-spacing: 0 }`；
2. 把字距收成 `--track-label` 令牌，中文模式改为 `0`。

第 1 种更省事，但依赖 L1 先修；这也是把 L1 定为「结构性」的原因。

### P2　数字等宽（基本满足，规范层待补）

`font-variant-numeric: tabular-nums` 全文只声明了 **1 处**：`.mono`（L254–256）。但所有数字输出类（`.stat b`、`.lbox b`、`.rbox b`、`.t-digits`、`.rx-groups`、`.p-stat b`、`.slog-kg`、`.hpr-ring b`、`.grb-gl b`、快照表数字）都用了 `font-family: var(--mono)`，而 `--mono` 以等宽字体结尾，数字本身不会跳动。

所以：**视觉上不改也不会抖**；但按「数字必须显式 tabular-nums」的规则，目前只有 `.mono` 满足。建议给所有 `font-family:var(--mono)` 的数字类统一补 `font-variant-numeric:tabular-nums`，作为防御（字体回退时不至于失去等宽）。

### P3　字重跨主题一致（通过）

三个令牌块与所有 `html[data-mode="light"]` 规则均未修改 `font-weight` / `font-family` / 字体平滑；`-webkit-font-smoothing:antialiased` 是全局单条（L242）。规则 C 通过，不编造问题。

需要说明的是：亮底深色文字在低对比度下**主观上会显得更细**（尤其 8px/800 的小标签），这是对比度问题（见 T1/T5），不是字重被主题改动。

### P4　中文孤字 / 截断风险（可疑）

窄容器里同时 `white-space:nowrap + overflow:hidden + text-overflow:ellipsis`、且承载中文的位置：
- `.dock-btn b/span`（L757–758）——中文日名可能被截成 1 个字；
- `.brand-sub`（L295，L7024 注释明确说窄屏靠单行省略）——中文日标题容易被截；
- `.aux-title` / `.panel-title`——长中文标题在 360dp 下可能只剩前半句；
- `.prog-chip`——数据层中文「推荐（次数 ≤6）」这类长值；
- `.lbox label` / `.rbox label`——「载荷/计划」本身短，风险低但同属一类。

这一类需要 360dp 真机截图确认是否出现孤字，本报告只列风险点，不定性。

## 6. 一句话结论

- **主题**：暗色是完整的；light/nature 的问题集中在「写死暗色字面量的文字与软底/细边」——`GL_RANKS` 五色、`.rx-groups`、`.sp-tag`、容量带、有氧冲突行、档案页 SBD 标签是必须修的；`--fig-*`、`--gear-*` 两类图形已经令牌化，是做得对的部分。
- **语言**：静态 i18n 表（243 条）质量很好，缺口集中在**非模板文案**——GL 段位大字、启动失败链、档位/导入校验、周期评估 notes，以及**数据层**的策略库矩阵/卡片、计划库 chips、HPR 单位、周备注。其中策略库矩阵是英文用户能天天看到的最大漏翻面。
- **排版**：中文吃字距是系统性规范问题；数字等宽靠 mono 字体已满足视觉要求；字重跨主题没有差异。修字距前先修 `<html lang>`，否则没有可靠的 CSS 作用域。

## 2 · 系数计算器

### 2.1 输入

| 字段 | 控件 | 取值范围 | 说明 |
|---|---|---|---|
| 性别 | `.seg-pill` 两段 | 男 M / 女 F | 影响三种系数的性别多项式 |
| 装备 | `.seg-pill` 两段 | 无装 classic / 单层 equipped | **只影响 IPF GL**；DOTS 与 Wilks 2 没有装备变体 |
| 体重 | 数字输入 | 35.0–210.0，步进 0.1 | GL 要求 ≥35；DOTS 内部钳 40–210 / 女 40–150，Wilks 2 钳 40–200.95 / 女 40–150.95 |
| 深蹲 | 数字输入 | ≥0，步进 2.5 | |
| 卧推 | 数字输入 | ≥0，步进 2.5 | |
| 硬拉 | 数字输入 | ≥0，步进 2.5 | |

打开面板时**从 `state.profile` 预填**（性别 / 装备 / 体重 / 三项），只读；用户改动只活在本面板内，不写回档案。这一点与 `refreshProfileCoefs()` 的写回路径必须分开——计算器不是编辑器。

### 2.2 输出

主结果卡（复用 `.gl-rank-bar` 骨架）：

1. **段位徽章** 48px（`rankIconHtml(id,48,false)`，symbol 见 §6.2）+ 段位名 + 星数（名称/星串取自 `calcGlRank()` 的 `labelZh` / `labelEn` / `starsStr`）
2. **IPF GL** 大号数字（`.grb-gl` 位），副行 `BP GL`（卧推单项 GL，可选，沿用档案页已有口径）
3. 距下一星的差值（沿用 `calcGlRank().deltaNext`）

明细（复用 `.lvl-row`，只读三行）：

| 行 | 值 |
|---|---|
| 三项总成绩 | S+B+D，`kg` |
| DOTS | `calcDots(total,bw,gender)`，两位小数 |
| WILKS 2 (2020) | `calcWilks2(total,bw,gender)`，两位小数 |

> 不新增第四个系数系统：`IPF GL` 的 PL / BP 两种用法是同一个公式的 `isBench` 开关。

### 2.3 交互

- **实时计算**：任一输入 `oninput` 即重算，不设「开始计算」按钮（与现有配重计算器一致，少一次点击）。
- **用我的档案数据**：结果卡右上放一枚 `.chip-s`，点一下把档案里的性别 / 装备 / 体重 / 三项重新拉进输入框（对应 `settings-ia.md` §5.2 ③ 的回填入口）；打开面板时默认已经预填一次，这枚胶囊只用于「改乱了想回去」。
- **全部重置**：回到打开时的档案预填值，而不是清成 0。
- **空值 / 越界**：体重 <35 时 GL 记 0 并给一行 `--warn` 提示；三项全 0 时结果卡显示 `—`，不显示「最低档 1★」这种「0 分也有段位」的假结论（段位函数本身会返回最低档，UI 侧要挡住）。
- **口径标签**：段位脚注写「本次计算口径 · IPF GL」，因为用户可能把装备切到 equipped 而与档案页段位不同，必须当场说明差异来源。

### 2.4 复用与不写盘

计算函数**一个都不新写**，只调用 `calcIpfGl` / `calcDots` / `calcWilks2` / `calcGlRank`。这保证计算器与档案页、LevelSnapshot 永远同源；第二份公式出现的同一天，两处就会开始互相打脸。

## 3 · RM 计算器

### 3.1 输入

| 字段 | 控件 | 范围 | 默认 |
|---|---|---|---|
| 重量 | 数字输入 + `−/+` | 0–500，步进 2.5 | 空 |
| 次数 | 数字输入 + `−/+` | 1–30，整数 | 5 |
| RPE（可选） | `.chip-s` 循环 5.0–10.0 | 步进 0.5 | 10.0 |

RPE 默认 10（= 真 RM）。带 RPE 时直接用现有 `e1rm(load,reps,rpe,targetRpe)`，它已经把 RIR 折进去，不另写公式。

### 3.2 输出

1. **估算 1RM** 大号数字（`e1rm()` 的返回值，保留 1 位小数）
2. **百分比表**：两列，每行 `次数 · %1RM · 重量`；输入次数那一行高亮（`.chip-s` 的 `--gold-soft` / `--gold-line` 反相即可，不新增高亮令牌）
3. 一行口径说明 + 低置信警示

表格行建议：

- 主区：1–12 次（两列 × 6 行）
- 展开区：13 / 14 / 15 / 16 / 18 / 20 / 22 / 25 / 30（截图里的常用档）

### 3.3 公式取舍（已自决：同源单表）

现有 `e1rm()` 是 `load × (1 + (有效次数 + RIR) / 30)`，且**有效次数在 12 次封顶**。为了让计算器与训练日志同源，采用：

```
e1RM      = e1rm(load, reps, rpe)          // 唯一公式，不新写
pct(r)    = 100 / (1 + r/30)               // 同一条曲线的反解
weight(r) = e1RM × pct(r) / 100
```

性质：**输入 100kg × 5 次 → e1RM 116.7，表格第 5 行正好回到 100.0kg**，用户能一眼验证表格没算歪。

代价（已接受）：第 1 行是 **96.8%** 而不是截图的 100%。因为 `e1RM` 本身是估算值，若把第 1 行硬写成 100%，就必须再引入一张固定百分比表（截图那张 1=100 / 5=87），项目里就有了第二份公式。`§8-Q3` 已按此拍板，并写明被否方案。

### 3.4 低置信必须显式（项目硬约束）

- `reps > 12`：公式在 12 次封顶，此时 `e1RM` 是**下界**。表格仍可看，但顶部必须挂 `--warn` 警示：「公式在 12 次封顶，>12 次为外推，仅供参照」。
- `reps = 1` 且未填 RPE：结果等于输入本身（1 次就是 1RM），不额外标注。
- 输入为 0 / 空：结果区整体显示 `—`，不出表，不用 0 冒充。

> **模式 B（已知 1RM + 目标次数 → 百分比重量表）本版不做。** 截图只有「重量 + 次数」一种入口，用户要的是截图功能。`settings-ia.md` §5.2② 若坚持双模式，B 可复用同一张 `pct(r)` 表，只换数据源、不新增公式，成本约一个切换胶囊；这一条不需要现在决定。

## 6 · 段位徽章：全 App 共享组件

> **硬约束**：段位徽章是**全 App 共享组件**，不是计算器专用资产。图形只有一个源（`rank-sprite.svg` 的 10 个 `<symbol>`），渲染只有一个入口（`rankIconHtml()`），所有界面用 `<use>` 引用。任何界面**不得**再写第二份路径、emoji、背景图或 `<img src>` 版本。

### 6.1 资产形态（符号片段，不是 10 个独立文件）

```
mobile/docs/design_v0.70/
├ rank-sprite.svg              # 唯一图形源：5 彩色 + 5 单色 symbol（含 5 条渐变）
├ preview.html                 # 校色页（内含 sprite 副本，仅预览用，非交付）
└ preview-full.png            # 无头 Chrome 实拍，非交付
```

- 原 `rank-1.svg…rank-5.svg` / `rank-N-mono.svg` 共 10 个独立文件**已删除**：独立文件要靠 10 段 `<img>` 或 10 次内联才能共享，正是「同一套图形存两份」的来源。改为符号片段后只有一份路径数据。
- `rank-sprite.svg` 的内容是一个 `<svg width="0" height="0">` 外壳 + `<defs>`（5 条渐变，id `rk-g-{tierId}`）+ 10 个 `<symbol viewBox="0 0 64 64">`。
- 档数仍由 `GL_RANKS` 决定（5 项，4450–4456 行）；新增档位时只加 symbol + 渐变，不改调用方。
- 图形里**不出现中文、不出现档位文字、不出现数字**；档名只来自 `GL_RANKS[*].zh/en`，symbol 内不含任何文本节点。
- 彩色 symbol 里除**渐变中段 = `GL_RANKS[*].color`** 之外，只有该色的暗端/亮端与白色高光；它们只服务金属质感，不承担档位识别，也不得出现在 UI 层——因此不构成第二套档位色值。

### 6.2 唯一渲染入口

**symbol id 命名规则**（由 `GL_RANKS[i].id` 派生，语义稳定、不靠数组序号）：

| symbol id | 用途 |
|---|---|
| `rk-bronze` / `rk-silver` / `rk-gold` / `rk-diamond` / `rk-master` | 彩色（金属渐变，跟 `GL_RANKS[*].color`） |
| `rk-{tierId}-mono`（同上 5 个） | 单色，只用 `currentColor`，由父级 `color` 染色 |

**唯一渲染函数**（建议放模板 `GL_RANKS` 之后的同一段）：

```js
/* 段位徽章的唯一渲染入口：任何界面要图标都调这里，不许自己拼 <svg><use>。 */
function rankIconHtml(tierId, size, mono){
  var s = size===48 ? 48 : (size===32 ? 32 : 24);   /* 只允许 24 / 32 / 48 */
  return '<svg class="rk-ico rk-'+s+'" width="'+s+'" height="'+s+'" viewBox="0 0 64 64" aria-hidden="true" focusable="false">'
       + '<use href="#rk-'+tierId+(mono?'-mono':'')+'"></use></svg>';
}
```

**调用方只写这一行**，不要复制任何 `<path>`：

```html
<svg class="rk-ico rk-32"><use href="#rk-silver"></use></svg>
```

**尺寸只允许三档**（CSS 三条类，不接受第四种；缩放靠 `width/height`，不改 `viewBox`）：

| 类 | 尺寸 | 必须用在哪 |
|---|---|---|
| `.rk-24` | 24px | 快照表、设置行、水平行、HUD 环心 |
| `.rk-32` | 32px | 档案页 `#glHero` 结果条（默认） |
| `.rk-48` | 48px | 系数计算器主结果、分享卡（若加） |

- **单色变体只对 `currentColor` 负责**：父级 `color` 取 `calcGlRank().color`（或主题 `--ink2`），不写死色号。
- **彩色变体不自带 CSS 色**：渐变写死在 symbol 内，其唯一依据是 `GL_RANKS[*].color`（见 §7.2），UI 层不准再声明第二份。
- 无障碍：图标是装饰，`aria-hidden="true"`；可读名称由旁边的 `labelZh / labelEn` 文本承担，不塞进 SVG。

### 6.3 引用方式（单文件 App 的唯一可行解）

1. **模板里内联一次**：把 `rank-sprite.svg` 的 `<svg>…</svg>` 整段粘进 `template.html` 的 `<body>` 顶部（建议紧邻图标常量区），**只此一处**。运行时不需要 `fetch`，不新增文件/网络权限。
2. **业务代码只用 `<use href="#rk-…">`**：`use` 在同一文档内才能解析；因此不能走 `<img src="…svg">`（离线单文件也没有外部文件），也不能用 `background-image`。
3. **渐变 id 全局唯一**（`rk-g-bronze` 等）：symbol 被多次实例化时共用同一条渐变，不会互相覆盖；新增 symbol 必须沿用该前缀。
4. **分享卡是 canvas**：`poster`（`computePosterData` → canvas PNG，约 10712 行起）不能直接 `drawImage` 一个 `<use>` 节点。若将来在分享卡上放徽章，必须把**同一个 symbol** 序列化为 data URI → `new Image()` → `drawImage`，**禁止在 canvas 里手绘第二套图形**。本版分享卡不加段位（现状也不加）。

## 7 · 段位判定规则（原样沿用现有实现，不自拟阈值）

> **档位与阈值抄自 `mobile/tools/template.html` 的 `GL_RANKS`（第 4450–4456 行）与 `calcGlRank`（第 4457–4475 行）。** 本节是对现有实现的转录，不是提案；本文件不另立第二套阈值或档名。
> 行号是本次读取的当次快照，定位时以符号名 `GL_RANKS` / `calcGlRank` 为准。

### 7.1 用哪个系数、几档几星

只用 **IPF GL** 判段——`calcGlRank(gl)` 的唯一入参就是 GL。DOTS 与 Wilks 2 是并列展示，不参与判段；现有 `currentGl()`、`LevelSnapshot`、档案页 `glHero` 全部锚在 GL 上，换锚点会同时改三处历史口径。

**五档**，左闭右开扫描（`s >= GL_RANKS[i].min` 取最后一个满足项），每档 5 星。

### 7.2 现有档位表（原样转录）

| # | symbol | `GL_RANKS[i].id` | `zh` / `en` | `min – max`（GL） | `step`（星步长） | `color` |
|---|---|---|---|---|---|---|
| 1 | `rk-bronze` | `bronze` | 青铜 / BRONZE | 0 – 45 | 9 | `#CD7F32` |
| 2 | `rk-silver` | `silver` | 白银 / SILVER | 45 – 60 | 3 | `#C0C8D4` |
| 3 | `rk-gold` | `gold` | 黄金 / GOLD | 60 – 75 | 3 | `#F3C97D` |
| 4 | `rk-diamond` | `diamond` | 钻石 / DIAMOND | 75 – 90 | 3 | `#38BDF8` |
| 5 | `rk-master` | `master` | 王者 / MASTER | 90 – 999 | 2 | `#F43F5E` |

星级与下一星，按 `calcGlRank` 原文口径（第 4463–4466 行）：

- `stars = min(5, floor((gl - min) / step) + 1)`
- `nextStarGl = (id === 'master' && stars === 5) ? null : min + stars × step`
- `deltaNext = nextStarGl != null ? max(0, nextStarGl - gl) : 0`
- 显示文案**不另写**，直接用函数返回的 `labelZh` / `labelEn`（形如「白银 3★」/「SILVER 3★」）与 `starsStr`（`★` × stars + `☆` × (5 − stars)，固定 5 格）。

> **`max` 不参与判定**：扫描只看 `min`，`max` 只是给人看的区间上界，`master` 的 `999` 是无上限哨兵。所以**第 6 档不存在**，sprite 里也没有第 6 个 symbol。

### 7.3 目视样例（用现有函数跑出来的，不是新算的）

用户档案（BW 87.5，S135 + B90 + D160 = 385kg，男子无装）→ `calcIpfGl` 约 **51.9 GL** → 落在 `silver`（45–60，step 3）：offset 6.9 → `floor(6.9/3)+1 = 3` → **白银 3★**，`nextStarGl = 45 + 3×3 = 54.00`，`deltaNext = 2.10`。

（DOTS 252.57、Wilks 2 299.71 只作并列展示，不影响段位。）

### 7.4 本版不动数值，所以不动断言

`GL_RANKS` / `calcGlRank` **一处都不改**。因此：

| 位置 | 结果 |
|---|---|
| `v3v.js` `N22a–N22e`（44.99 → 青铜 5★、45.00 → 白银 1★、89.99 → 钻石 5★、90.00 → 王者 1★、98.00 → 王者 5★） | **保持绿**，期望值不动 |
| `logicv.js` rank 段边界采样 | 保持绿 |
| `GL_RANKS` 消费者（`refreshGlHero`、`renderLevelSnapTable`、`calcGlRank` 返回的 `color/bg/line`） | 不受影响 |

**唯一新增物是图形**：现有系统只有档名字符串 + 色带，没有奖牌图标（`#glHero` 只渲染文字与色条）。所以本版是「**只补图形，不动数值**」。

### 7.5 段位与「本次计算口径」

系数计算器允许用户切装备，而 IPF GL 是三种系数里唯一吃装备的，因此它算出的段位可能与档案页不同。这是预期行为，但结果卡必须写明「本次计算口径 · IPF GL / 装备 X」，不能只放一枚徽章让用户以为档案被改了。

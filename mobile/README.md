## 3 · 命令与守卫

**环境前提**：`JAVA_HOME` 指向 Android Studio 自带 JDK 17；`local.properties` 有 `sdk.dir`；`maven.google.com` 本机不可达，因此**必须加 `--offline`**。

### 3.1 · 构建

```bash
cd mobile
pip install -r tools/requirements.txt     # 仅 gen_seed/rxlib/gen_icon 需要；APK 本身零依赖
python tools/pack.py                      # 静态守卫 + 注入 + 构建 + 规范命名 + 发版门禁 + 校验，一条命令
```

`pack.py` 等价于手工三步（出现问题时用它们定位）：

```bash
export JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
python tools/build_html.py
./gradlew --offline assembleRelease        # Windows cmd: gradlew.bat
cp app/build/outputs/apk/release/app-release.apk \
   ../release/RPL_ExDark_v{versionName}_Pro.apk    # 版本号取 build.gradle，别手抄
```

调试包：`python tools/pack.py --debug`（只构建到 `app/build/outputs/apk/debug/app-debug.apk`，不覆盖 `release/`）。
`release` 用 debug 签名（`signingConfig = signingConfigs.debug`），用于自用侧载，不上架。

### 3.2 · 运行

```bash
export MSYS_NO_PATHCONV=1
ADB="C:/Users/Astra/AppData/Local/Android/Sdk/platform-tools/adb.exe"
VER=$(python -c "import sys;sys.path.insert(0,'tools');import build_html;print(build_html.read_version()[0])")
"$ADB" shell pm clear com.roast.exdark        # 换 APK 验收前必做，否则旧存档污染判断
"$ADB" install -r "../release/RPL_ExDark_v${VER}_Pro.apk"
"$ADB" shell am start -n com.roast.exdark/.MainActivity
"$ADB" shell dumpsys package com.roast.exdark | grep version   # 应与 build.gradle 的 versionName / versionCode 一致
```

`v3v.js` / `v2v.js` 用的是 `file:///…/app/src/main/assets/index.html`，即**成品**，不是模板；所以改完模板必须先 `build_html.py` 再跑回归。

### 3.4 · 断言自体检（v0.07 新增，别绕过它）

历史教训：v0.06 之前 `v2v.js` 无条件 `exit(0)`，断言写错也永远「全绿」，于是「boot 恢复失败会清空训练账本」这条静默数据丢失一路活到发版。所以仪表盘不仅要能跑，还要**证明它会红**。三份机制：

| 项 | 作用 | 失配时的表现 |
|---|---|---|
| `A0 依赖的前端 API 全部存在` | 开跑前点名：断言块直接调用的前端函数有没有被改名/删掉 | `FAIL [缺失: openProgLibSheet]` |
| `Z0 断言块在 X 段中途抛错` | 整块包了 `try`，中途崩也保住已跑出的结果并报出崩在哪一段 | `FAIL … [ReferenceError: … ]`，其后 `Z1` 同步红 |
| `Z1 断言总数无漂移` | 条数闸门（`EXP_N` 只写在每个脚本自己的常量里，不在本文手抄；取法：`grep -n "EXP_N = " tools/*.js`）；删一条、或整段被 `if` 跳过都会掉数 | `FAIL [实到 55 应 <EXP_N>]` |

**改断言时必须同步 `EXP_N`**，否则 `Z1` 红。验证「测试本身有效」用反向故障注入，注入家族全家列在下面。

**通用跑法**（组号对应哪处故障、期望红在哪一条，**唯一出处是每个脚本自己的 docstring**——
就在文件头，`tools/_sabotage_m8.py:2` 起那一段；全家名单 `ls tools/_sabotage_*.py`。
本文只留名单与跑法，不抄第二份逐组清单——抄了就必然先腐烂，这是红线 3）：

```bash
cd mobile
python tools/build_html.py                                    # 先取一份干净成品
python tools/_sabotage_c2.py 3 && node tools/v3v.js            # 只改成品的家族：组号见脚本头
python tools/build_html.py                                     # 这类家族一条 build_html 就复原

python tools/_sabotage_m8.py inject 2 && python tools/gate.py --static   # 带台账的家族
python tools/_sabotage_m8.py revert && python tools/gate.py --static     # 逐字节还原，不依赖 git
```

**上面那一串现在有一条命令能代跑**（v0.30 起的 `tools/sabr.py`，只覆盖带台账的那十几家）：

```bash
python tools/sabr.py list n2                 # 这一家有几处靶、各自期望红在哪条腿
python tools/sabr.py run n2 45 --with ui     # 清台账 → 注 → 重建 → 跑 → 对账 → 还原 → 重建 → 复跑回绿
python tools/sabr.py run w1 1 3 6            # 默认只跑静态层（秒级）；--with fast/ui/all 逐档加回归
python tools/sabr.py run b4 --with plan      # inject() 不收参数那几家：不给靶号，整族合注、期望取并集
python tools/sabr.py selftest --live         # 查这台驱动器自己会不会红（故意报错期望，必须判 FAIL）
python tools/sabr.py check                   # 不注入：只看台账残留 + 哪些家它认得
```

它把上面那两条手工仪式里最容易忘的四件事变成判定：注入前台账必须空、期望那条腿必须红、
还原后**自己算哈希**逐字节对账（不信 `revert` 的口头回执）、复跑必须回绿。期望从各家的
`EXPECT` 表里现读，不在本文抄第二份。三个已知边界都写成判定而不是留白，`check` 会逐家点名：
① **import 期就自己读 `sys.argv` 的那九家**（a5 / c1…c5 / c6 / l1）它不碰：其中 a5 / c1…c5 / l1
是「只改成品」的形状，复原本来就是一条 `build_html.py`、没有台账可对，照上面的人肉跑法；
`c6` 虽有台账，但同样在 import 期 `sys.exit(__doc__)`。驱动器拒绝迎合那种形状——
硬凑参数等于替它动手注入，那是越权不是便利。
② **`t1` 没有 `inject` / `revert` 这对入口**，判「认不出」而不是硬猜；它的故障压在仓库索引上，
注入态一次顺手 `git commit` 就把探针永久写进历史，**任何时候都不许由驱动器代跑**（见下面跨切第 6 条）。
③ **`--with` 没开到的层不冒充核对**：期望点了 uiv 而只跑静态时，本条判 SKIP 并说明缺哪层；
反过来 EXPECT 只写腿名不写套件名的老写法（`n2` 的 F22「LD15 红 + S19 红」）在静态层取不到那条腿，
会判 FAIL 并把实到全列出来——那不是断言没牙，是开的层不够，`--with fast` 重跑即绿（实测）。
④ **`inject` 有两种形状，按签名认、不试错**：`inject()` 不收参数的那几家（a6 / b4 / b5 / m1 / m2）
一注就是全族，所以**不给靶号**（`python tools/sabr.py run b4 --with plan`），驱动器整族合注一条判定、
期望取全族并集；这时给靶号会被忽略并在第一行打印「整族合注 N 处」，不会假装只注了一处。
`inject(pick=None)` 收 1 基整数的（m3…m9 / n1 / n2 / r1 / u1 / w1）按单点注。
为什么看签名而不是「先当单点打、吞掉 `TypeError`」：那家在已经改完一半磁盘之后才抛错，
试错法就留下半注入状态（m5 的第 3 条实测这么留过），还原时对不上账。
⑤ **S26 的两条腿拆开算**：S26 既盯「四处版本指针跟 gradle 不等」，也盯「`tools/` 下还有台账残留」，
而后者在**任何**一家的注入态都红——那是这台驱动器自己留下的痕迹，不是靶有牙的证据。所以 S26 只有当它
detail 里除了残留还报了版本指针漂移才计入实到（`run r1 1 2 3 4` 四条实测 PASS）；改模板那几家在静态层
看到的那条 S26 会被摘掉，不淹进「意外红」里。只看「S26 红了」就当 `r1` 的指针腿有牙是恒真断言（红线 6），
`selftest` 里有四条 detail 拆分的出口钉着它。`r1` 的 F5（造一份假台账）在 `inject 5` 那个分支里、
不在 `FAULTS` 表上，驱动器只认 1..4，那条腿照它自己的 docstring 人肉跑。

> **两种调用形状**（v0.20 终验时踩过，写在这里免得再踩）：带台账的那十几家用 `inject [N]` / `revert`，
> 只改成品的那几家（a5 / c1 / c2 / c3 / c4 / c5 / l1）用 **positional 组号**（`_sabotage_c2.py 3`，
> 不给参数就打印用法并 exit 1）。批量复跑时**别把 stdout 丢进 `/dev/null`**——形状不对时脚本什么都没注入，
> 门禁照旧全绿，读起来像「这一家已经不会红了」，其实是自己没打进靶子（§7 第 4 类坑：探针自身失效）。

   一个跟踪项 / 多一个孤儿 / 多一本在仓里的书」，一次顺手提交就把探针永久写进历史，`revert` 也拿不回来。跑法固定为
   `inject → --static → revert`，收尾多核一条**索引复原**（`git status --porcelain` 的行数与注入前
   一致）——光看 gate 回全绿不够，全绿只证明工作树干净，不证明索引没被探针污染过。
   v0.31 换边界后六组实测（静态基数与判据都取当刻 `gate.py` 的输出）：F2 只红 ③ / F3 只红 ② /
   F4 只红 ① / F5 红 ④+①（同一坏法两个观测面）/ F6 只红 ④ / F1 红 ①+③ 并连带 S26「残留台账」；
   六处合注一次报全；每组 `revert` 后 `--static` 回全绿，索引复原按上面那条实测过——F5 / F6 单注再
   revert 后 `git status --porcelain` 行数与注入前同为 1（那 1 行就是本文档自己的未提交改动）。**F6 的一条硬约束**：
   挪出去的暂存位必须落在被 ignore 的目录（`.sabotage-stash/`）——实测暂存放顶层会让 F6 连带红 ①，
   「被挪走的那本书自己」变成第二个故障，隔离就没了。

外加一条**关于探针自己**的规矩（v0.17 由 `_sabotage_m7.py` 教出来）：S22 把工具侧「引号 + 点 +
名字」形式的选择器也算「有人发」，所以注入用的类名**不许在同一个脚本里带点写成选择器**——写进去的
那一刻脚本就把自己注入的故障救活了，看起来像「没有死代码」。这是 §7 第 4 类坑（探针自身失效）的新形态。

S23 会不会被牵动，取决于**那处故障有没有压在别的脚本的靶串上**，不取决于脚本类别：压在别人靶串上
（同一个被检文件里改掉了别人要匹配的原文）就连带红，没压着就不红。v0.17 全家复跑实测：带台账的家族
在「台账在 = 注入态」这条规则下都不再牵 S23；`c3` / `c5` 会连带，`c2` 不会。

### 3.5 · 构建链守卫 `gate.py`（v0.07 新增）

红线（§5）过去只是文档，靠人记得住。`gate.py` 把它们变成会失败的检查：**取不到被检对象一律算 FAIL，不放行**。

| 号 | 守什么 | 对应的红线 |

## 5 · 红线（改了就会坏）

下列 1/2/3/4/5/9/13 已有 `tools/gate.py` 静态检查（S1~S27）代劳，改坏了会在 `gate.py` / `pack.py` 第 1 步当场报错；6/7/8/10 仍靠人守（7 的坐标一致性由 `wkbook.py` 单点定义保证，8 由两端回归保证）。11 由 gate 的 D6/D7 代守：「三处同一份」是 `build_html.py` 只读那一个 JSON，「不碰 24 表」是 `test_plan_xlsx.py` 的 T4 —— 四种落盘操作后源表 sha256 与 `data/` 目录内容都不许变，且源码里不许出现 `"data"` 路径或 `rxlib` import。

1. **不手改 `app/src/main/assets/index.html`** —— 它是生成物；改模板再 `build_html.py`。
2. **不写死版本号** —— 模板只允许 `{{VER}}`，`build_html.py` 会拦下 `v0.03` 这类硬编码。
3. **`versionName` 只写纯版本号**（`0.03`），不写 `0.03-Pro`；产品标签 `Pro` 是显示串，不进 `versionName`。界面品牌串与交换信封里的产品名同源于契约 `tools/schema/RPL-Exchange-v1.json` 的 `app_name`（现值 `RPL ExDark Pro`），别在模板或文档里另抄一份。退役标签 `ProMax` 不许再回到新文件名（APK 模板见 `tools/pack.py`）与可见文案（`v3v.js` 的 A5/N2 盯着后者）。
4. **不改 `applicationId` / `namespace`**（`com.roast.exdark`），改了旧存档与侧载升级全部失联。
5. **不改 CSV 列序 / 列名 / `schema_ver` 判定** —— 这 26 列的权威出处是 `tools/schema/RPL-Exchange-v1.json` 的 `log_jsonl.record_keys_frozen`；改名或换序属于**协议变更**，必须新增 schema 文件并把日志升版为 `RPL-Log-v2`、登记进 `accepted`，不许就地改。S7（契约/模板/成品三端）+ T8.0/T8.1b/T8.1c 一起拦。
6. **不删 `../data/*.xlsx`** —— 唯一权威源，删了种子不可再生。
7. **`W{n}` 行坐标只改 `tools/wkbook.py`** —— 它是唯一来源，读者是 `gen_seed.py`（PC 端曾共用，v0.13 起已归档）；改完必须重跑种子、重打包、跑双端回归（App 侧 `xlsxv` + Python 侧契约套件）。

    → 探针是 `` `(function(){...})` `` 模板串，串里的 `\d` / `\|` 到页面变成 `d` / `|`（`|` 还成了交替），判定看起来「全绿」其实什么都没查；**对策**：模板串里的正则一律用字符类 `[0-9]`、`[|]`，或写成 `\\d`；`\r\n`、`\uFEFF` 这类已知转义序列可以直接写（模板串会照原样传到页面）。

    → 只改 `structure.totalWeeks` 而留着种子的 16 周块表，回装时 total 由 Blocks 求和重新算出 16，于是凭空多出 12 周、`profile.planWeeks` 与块表求和也被契约交叉校验判 error。这类红是**用例的错不是页面的错**；**对策**：随机件同时重建与 total 相符的块表并写 `profile.planWeeks`，周数上限取种子周数（`week` 的合法区间就是 1..16，越界会被 `xPlanDictToState` 直接拒）。

18. **SVG 里的类名用字符串拼接出来，静态守卫就查不动它**（v0.15 图版踩到，也是 S20 存在的原因）
    → `'<circle class="fx-f' + k + '"'` 这种写法，源码里根本不存在 `fx-fsq` 这个名字，任何「类名必须在 CSS 里有定义」的检查都只能看到 `fx-f` 这个前缀；打错一个字母的表现是**那个图形没颜色**，不报错、不变红。**对策**：映射收进明面表（`FIG_LN` / `FIG_FN`），S20 拿表的键值与 CSS 定义做双向对账，并单独禁掉 `['"]fx-[a-z]*['"] +` 这种拼接写法。
19. **反向验证脚本自己会腐烂：靶子漂了 + 半注入残留**（v0.15 复跑 `_sabotage_m3.py` 踩到）
    → 两个坑叠在一起：① F2 的目标串抄的是 `gen_seed.py` 里的工作簿名，而那个名随种子链改过（v0.03 → v0.14），于是「目标串没找到」在**注入到第二处时**才发生——第一处已经改到磁盘上、台账却还没写，`revert` 于是报「没有台账」，故障永久留在工作区（本轮 `pyout.py` 就是这么被留下两行归档路径字面量的，得手工删）。② 这类脚本一旦打不红，看起来和「守卫很稳」一模一样，没有任何信号。**对策**：`_sabotage_m3.py` 改为先逐条验靶（存在且唯一）再动手写，任一条不合格就一处都不改；F2 的靶子改为从 `gen_seed.py` 现读 `XLSX` 那行，不再抄名字。**接手者口径**：每次改版复跑全部 `_sabotage_*` 家族，但**只核「红在哪几条」，不核 PASS 的数字**——基数随静态项数变（v0.15 复跑实测：m3 F1/F2 各只红 S18/S8、F3 红 S5+S7+S17、合注红 S5/S7/S8/S17/S18；m4 四组各红 S19+S5；a6 合注红 S2/S3/S5/S7/S13）。
    → **v0.17 加了 S23 之后补的口径**：S23 核对每个脚本的靶串，而注入态下那个脚本自己的靶串当然正被故障改走，于是**家族里每注一次、S23 就跟红一次**——噪声大到能把「只红自己那条腿」这件事核不下去。判据改成看**台账在不在**：`_sabotage_<同名>.json` 还在就跳过该脚本并在 detail 里点名（`m5`/`m6`/`m4`/`a6`/`b5`/`m1`/`m2`/`m3` 复跑实测：注入态都不再牵动 S23，各自只红目标那条腿，逐组的红名单见 §8 v0.17 那行）。**还剩一类噪声没消**：不写台账、只改生成物的脚本（`build_html.py` 就是它们的复原）——`c3` F7/F8 与 `c5` 各组仍会把 S23 一起带红，而 `c2` 的 F5/F6 不会：**红不红取决于那处故障有没有压在别的脚本的靶串上，不取决于脚本类别**，所以只能逐组看目标腿，别按类别猜。看目标腿就行，`build_html` 之后必然消失。**别为了消这点噪声去弱化 S23**：它在平静态核对 90 处靶串，本版就是靠它抓到两处已经腐掉的靶。

20. **动效没有最终态可断言，所以「写死一处时长」永远不会变红**（v0.16 踩到，也是 S21 存在的原因）
    → uiv 量的是动画落地之后的矩形，而中间帧本来就不可断言：漏改一个 `.3s` 不改变任何一套回归的结果，只让手感慢慢散开（原先 13 处各写各的，改一次「面板入场快一点」要满文件找）。**对策**：时长与缓动收进 `:root` 的 `--dur-*` / `--ease-*` 一条令牌链，CSS 里一律 `var()`；S21 拿声明段做双向对账 + 禁字面时长（唯一例外是减动兜底块）。由此得到两条**设计约束**，接手时别当怪事：① **面板不做关闭动画**——`.on` 必须同步消失，否则 uiv「点关闭→立刻量面板还在不在」会红，动效只做入场；② **动画只碰 opacity / transform / box-shadow，绝不碰几何**（宽度、内边距、位置）——中间帧落在几何上，uiv 的量测就成了「随机时刻快照」，四档宽度全红。真正查得出动效的方式是**非几何**的：宽度全程恒定（M8）、卡片是否亮过 `.just` 类、令牌有没有落地（M1/M2/M3）；`@media (prefers-reduced-motion:reduce)` 那条兜底是令牌化的收益，不是装饰。
21. **UI 探针读的是瞬时状态，读法错了就恒真或恒假**（v0.16 M 段连踩四次）
    → ① **toast 1800ms 自清**：`toggleDone` 一串打完后第一次读文本必然对得上，第二次读到的却是空串——读之前必须 `clearTimeout(toastId)` 并复位，断言要写成「第一次出现 / 已完成后不重复出现」这种**时序**判据，不能只比字符串。② **关着的 `.sheet` 里的 `<input>` 不可 focus**：`document.activeElement` 停在 `body`，看起来像焦点链坏了，其实是靶子没打开；**对策**：M6 / v3v 的 Y5 先 `openEditor(0)` 再量、再 `closeSheet`。③ **`ev()` 返回的是真布尔**：写成 `=== 'false'` 永远不成立，该条恒真。④ **`settle()` 只等有限时长的动画**：列表里混进 `animation-iteration-count:infinite` 的常驻脉冲（`.pulse.live`）会一直 `play`，整段回归挂死。
22. **故意不带样式的挂载点类会被 S22 判成「发出的 class 没有规则」**（v0.17 清死代码时定下的口径）
    → 有些容器类只是给 JS 找节点用的（`day-sub` / `jts-recsets` / `pv-sleeve`），DOM 里在、CSS 里没规则，S22 的反向腿就会报。**别把规则补上去凑绿**，那样等于给一个没人设计的元素凭空上色。**对策**：把它加进 S22 里那张 `hooks` 白名单（一行名字 + 一句为什么）；反过来，一旦真给它上了色，就把名字从白名单删掉——白名单只放「确实不该有规则」的类。**判据**：白名单变长是设计决策，不是修 bug；每条都要能说出这个类为什么永远不上色。

23. **`MSYS_NO_PATHCONV=1` 是双刃剑：它救 adb 的远端路径，也会打断 git 的本地输出路径**（v0.31 实测）
    → 设了它再跑 `git bundle create /c/Users/.../x.bundle --all`，报
    `Unable to create '/c/.../x.bundle.lock': No such file or directory`——目录明明是存在的，**MSYS 把 `/c/...`
    原样交给了 Windows 版 git，那边不认这种前缀**。**对策**：给 git 传输出路径的这一条命令**不要**带
    `MSYS_NO_PATHCONV=1`（或把路径写成 `C:/...`）；只有 adb / 设备侧路径才需要它。与 §6 第 3 条是同一个根因的两个方向，
    别再记成「凡是 Git Bash 就 export 一下」。
24. **新 clone 必然缺 `ref/`，S27 的 ④ 会如实判红——这不是仓库坏了**（v0.31 参考库出仓后）
    → 库不入仓，所以 `git clone` / `git bundle` 还原出来的目录没有那 96 本书，静态门禁当场红一条。
    **别去放宽判据凑绿**（那正好把「出处断链」这条真缺陷也一起放过）。**对策**：从本机副本或备份位把 `ref/`
    拷回仓库根，再跑 `--static`；取法写在 `data/00_索引/DATA_MAP.md` §1，备份位在 `Desktop/RPL-backup/`。

## 7 · 工作协议（给下一个接手的 Agent）

- **不确定就问，不要猜。** 该问的三类：
  - **A 可能大量耗时或耗 token**：全量重建、全量回归、批量重生成资源。
  - **B 破坏性**：删除、覆盖、重命名、移动目录。
  - **C 语义不确定**：共享数据归属、单源还是双份、命名、版本归属。
  一次最多 4 问，每问给出推荐项与理由。
- **动手前先跑验证命令建立基线**（一条命令）：`python tools/gate.py` —— 静态 S1~S27 + §3.3 的八套回归全过才算干净基线；各项判据数字以脚本里的 `EXP_N` 与 `gate.py` 的 `DYNAMIC` 为准，本文不抄。改动后必须再跑，结果写进 §8。碰过动作库代码（`rxlib.py`）时追加归档 PC 端里的 `test_library.py`（须先 `cp` 副本并 `--xlsx` 指向它；v0.13 起它不在门禁内）。
- **改动后必须重写 §1、§2、§6、§8**（版本、目录、坑、日志），其余按需。
- **破坏性操作前先快照**（`archive/snapshots/snapshot_YYYYMMDD_HHMM_<原因>.zip`），快照路径写进 §8。
- **不确定时默认动作是「停下来问」**，不是「先做一半」。
- **判断优先于服从**：若要求会破坏数据或留下不自洽的仓库，先提异议再执行。
- **预算紧张时的优先级**：README 与硬依赖裁决 > 物理移动 > 命名美化。

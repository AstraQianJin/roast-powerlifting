## 1. 为什么没有把 `00_META` 写进工作簿

主工作簿的 `W1–W16` 中，`LOAD`、`PROTOCOL`、`RPE` 等列是 Excel 公式，`gen_seed.py` 以 `data_only=True` 读取缓存值。

用 `openpyxl` 保存该工作簿会**清空公式的缓存值**，导致 `gen_seed.py` 读到 `None`，进而把负荷当成 0、组次协议为空。因此本轮：

- **不修改主工作簿**；
- 元数据与数据字典放在本文件和 `04_生成物/05_主工作簿数据字典.csv`；
- 修改前备份在 `05_归档/04_工作簿备份/RPL_ExDark_v0.03_ProMax_pre_meta_2026-11-02.xlsx`。

如果未来必须写入，请使用 Excel/WPS 打开并保存，或使用保留缓存值的工具；不要用 `openpyxl` 直接保存。

## 2. 工作表所有权

| 工作表 | 内容 | 权威性 | 备注 |
|---|---|---|---|
| `信息` | 运动员画像、1RM、目标、恢复、日程 | input | `gen_seed.py` 读取 `D10–D16`、`E10–E16`、`H6`、`H14`、`H15` |
| `周期` | 16 周块/阶段/T1/T2 百分比/RPE/组数 | input | `G` 列 RPE 被回填为 `baseRpe` |
| `W1`–`W16` | 每周 4 个训练日的处方、遥测、AUX | input | 固定行段；不要插入行/列 |
| `动作库` | 动作/分类/层级/标签 | input | 240 个唯一英文名、32 个分组、19 个跨分类重名 |
| `映射` | 分类 → 动作组 → 数量 | input | 主项计数与实际不一致 |
| `协议` | 24 个做组模式 | input | 旧名 SS/SL/T1.Def/T1.S2/T1.S3 仍在用 |
| `Exe` | 展示页 | derived | 不参与 seed |
| `总览` | 周/日容量仪表盘 | derived | 与处方重复，当前 77 vs 87 组不一致 |
| `追踪` | 16 周 e1RM/体重/吨位 | demo/derived | 预填演示数据，`gen_seed` 不读取 |

## 3. 已知问题（与数据质量报告一致）

1. **负荷口径不一致**：W1 深蹲 92.5kg = 1RM 135kg 的 68.5%，而 `周期` T1 写 76%；W1 硬拉 87.5kg = 165kg 的 53%。
2. **组数不一致**：W1 按协议实际 87 组（A 23 + B 23 + C 22 + D 19），`总览`/`周期` 写 77。
3. **旧模式名**：`SS` / `SL` / `T1.Def` / `T1.S2` / `T1.S3` 依赖 `gen_seed.py` 的 `MODE_MIGRATION_MAP` 迁移；`T1.6x6` 不在工作簿。
4. **演示遥测**：`追踪` 与 `W` 表预填了体重、睡眠、HRV、时长等演示值；`gen_seed` 会把遥测置空。
5. **动作库无稳定 ID**：跨表连接只能靠名字；辅助动作库 139 个名字不在动作库。
6. **版本脱节**：工作簿标题写 v0.01、文件名 v0.03、App 已到 v0.07。

修复建议见 [DATA_STRUCTURE_v1.md](./DATA_STRUCTURE_v1.md) 与 [数据质量报告](../04_生成物/04_数据质量报告.md)。
